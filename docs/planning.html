1개요 및 목표

웹 브라우저, Outlook 메일 본문, 탐색기, 문서 뷰어 등 스크롤이 가능한 모든 Windows 프로그램에서 화면에 보이는 부분만이 아니라 스크롤 끝까지의 전체 내용을 하나의 이미지로 저장한다. 브라우저 확장처럼 특정 앱에 종속되지 않고, OS 수준의 마우스 휠 입력과 화면 캡쳐로 동작한다.

항목내용
제품명ScrollCapture (저장소: scroll-capture)
플랫폼Windows 10 / 11 (x64)
배포 형태단일 실행 파일 ScrollCapture.exe (설치 불필요, 포터블)
개발 언어Python 3.11+
공개 범위GitHub Public 저장소, MIT License, GitHub Releases로 배포
핵심 가치① 앱 무관 ② 클릭 3번 이내 완료 ③ 이음새 없는 결과물 ④ 가벼운 단일 exe

성공 기준

  • Chrome / Edge 웹 페이지, Outlook(클래식·신규) 메일 본문, 메모장, 탐색기 목록에서 이음새(중복/누락 줄) 없이 끝까지 캡쳐
  • 일반 웹페이지(약 10화면 분량) 캡쳐 완료까지 15초 이내
  • exe 크기 80MB 이하, 첫 실행 3초 이내

3사용자 흐름

① 실행 / 단축키 Ctrl+Shift+S→ ② 캡쳐할 창 클릭→ ③ 스크롤 영역 확인 (자동 감지)→ ④ 자동 스크롤·캡쳐 (Esc 중지)→ ⑤ 미리보기 / 크롭→ ⑥ PNG·JPG 저장

5캡쳐 · 스티칭 알고리즘

5.1 캡쳐 루프

1. Per-Monitor DPI Aware v2 설정 (좌표/픽셀 불일치 방지)
2. 대상 창 전면 활성화 (SetForegroundWindow, 최소화면 ShowWindow(SW_RESTORE))
3. 스크롤 영역 R 결정 (자동 감지 또는 사용자 지정)
4. [옵션] 휠 위로 반복 → 화면이 2회 연속 변하지 않으면 맨 위 도착
5. frame[0] = capture(R)
6. loop:
     SendInput(MOUSEWHEEL, -WHEEL_DELTA × n) at center(R)    # n = 설정값, 기본 R높이의 ~70%
     wait(설정 대기시간, 기본 250ms) + 화면 안정화 대기(연속 2회 동일 시까지, 최대 1s)
     frame[i] = capture(R)
     if frame[i] ≈ frame[i-1] → same_count++ ; if same_count ≥ 2 → 끝
     if 누적 높이 ≥ 최대 높이(기본 30,000px) or Esc → 끝
7. 커서 위치 원복, 스티칭 단계로
캡쳐 방식: 기본은 화면 픽셀 복사(mss / BitBlt) — 하드웨어 가속 앱(Chrome, Edge, 신규 Outlook)에서도 확실히 동작한다. 캡쳐 중에는 HUD를 R 바깥에 두고, 마우스 커서는 캡쳐에 포함되지 않는다.

5.2 스크롤 영역 자동 감지

  1. 창 클라이언트 영역 중앙(또는 클릭한 지점)의 지점을 포함하는 가장 작은 보이는 자식 창(EnumChildWindows, Chromium의 투명 렌더 위젯 포함)을 기준 영역으로 삼는다.
  2. 자식 창 구조가 없는 앱(Chromium, WebView2)은 시험 스크롤: 한 번 휠 후 전/후 프레임 차분으로 “변한 영역”의 바운딩 박스를 스크롤 영역으로 채택하고 원위치(휠 역방향).
  3. 결과가 부정확하면 사용자가 드래그로 수정.

5.3 겹침 계산 & 합성

  • 고정 영역 제거: 연속 프레임에서 상단/하단 행이 픽셀 단위로 동일한 구간 = 고정 헤더/푸터. 중간 프레임에서는 잘라내고 첫 프레임 헤더·마지막 프레임 푸터만 사용.
  • 오프셋 탐색: 고정 영역을 뺀 본문에서 각 행을 8개 열 구간으로 나눠 64비트 해시를 만들고, 내용 있는 행-구간이 가장 많이 정확히 일치하는 이동량 dy를 찾는다(일치율 90% 이상). 실패 시 그레이스케일 축소 시그니처의 절사평균 차이로 허용오차 매칭. 떠 있는 버튼처럼 함께 움직이지 않는 요소는 하단 띠로 감지해 푸터처럼 처리하고, 스크롤바 열은 잘라낸다.
  • 합성: 새로 드러난 dy만큼의 행만 이어 붙임. 메모리 절약을 위해 numpy 배열 리스트로 보관 후 마지막에 한 번 vstack.
  • 예외: 애니메이션/동영상/캐럿 깜빡임 대비 차분 허용 오차, 오프셋 0 연속 시 종료 판정.

6프로그램 디자인 (UI)

디자인 원칙: 작고 단순한 메인 창, 캡쳐 중에는 방해하지 않는 HUD, 편집은 별도 창. Windows 11 Fluent 스타일(라운드 6px, 시스템 강조색 #2F6FED 계열), 시스템 라이트/다크 테마 자동 추종. 기본 폰트 맑은 고딕 / Segoe UI.

UI 언어: 한국어 / English 2개 언어 지원. 첫 실행 시 Windows 표시 언어를 따라 자동 선택(한국어 외에는 영어), 설정 → 일반 → 언어에서 변경. 문자열은 키 → (한국어, 영어) 사전(i18n.py)으로 관리하며, 영어 문구가 한국어보다 길어지는 점을 고려해 버튼·라벨은 고정 폭 대신 자동 폭으로 배치한다.

9저장 사양

항목사양
기본 형식PNG (무손실, compress_level 6)
JPG품질 기본 90 (설정 60–100), 4:4:4 서브샘플링(글자 번짐 방지), 투명 없음
파일명ScrollCapture_{창제목}_{YYYYMMDD_HHMMSS}.png — 파일명 금지문자 치환, 제목 40자 제한, 중복 시 _1 증가

10빌드 · 릴리즈 · 배포

빌드

python -m venv .venv && .venv\Scripts\activate
pip install -e .[dev]
pyinstaller scrollcapture.spec      # → dist\ScrollCapture.exe (--onefile --windowed, icon.ico, 버전 리소스 포함)
  • exe에 Windows 버전 정보(파일 버전, 제품명, 저작권) 리소스 삽입
  • 용량 절감: OpenCV 미사용(numpy만), PySide6-Essentials만 사용, 불필요한 Qt 모듈(QtWebEngine, Qml 등) 제외, UPX 미사용(백신 오탐 방지)

릴리즈 (GitHub Actions)

  1. vX.Y.Z 태그 푸시 → release.yml 실행 (windows-latest)
  2. 테스트 → PyInstaller 빌드
  3. 산출물: ScrollCapture-vX.Y.Z-win-x64.exe, ScrollCapture-vX.Y.Z-win-x64.zip(exe + LICENSE + THIRD_PARTY_NOTICES + README), SHA256SUMS.txt
  4. CHANGELOG의 해당 버전 섹션을 릴리즈 노트로 사용해 GitHub Release 자동 생성
SmartScreen 경고: 코드 서명 없는 exe는 첫 실행 시 “Windows의 PC 보호” 경고가 뜬다. README에 “추가 정보 → 실행” 안내와 SHA256 검증 방법을 명시. 추후 코드 서명 인증서 검토.

버전 규칙

Semantic Versioning. 0.x = 베타, 1.0.0 = MVP 완료. 버전은 src/scrollcapture/__init__.py의 __version__ 단일 출처.

13리스크 및 대응

리스크대응
부드러운 스크롤(smooth scrolling)로 캡쳐 시점에 화면이 움직이는 중캡쳐 전 연속 2프레임 동일할 때까지 대기(안정화), 최대 대기 1초
sticky 헤더, 플로팅 버튼, 지연 로딩 이미지고정 영역 감지·제거, 매칭 시 하단 띠의 여러 위치 후보 비교, 대기 시간 설정 제공
반복 패턴(표, 빈 줄)으로 오프셋 오검출휠 입력량으로 예상 이동량 범위를 제한해 탐색, 신뢰도 낮으면 행 해시 보조 검증
DPI 배율 차이로 좌표 어긋남Per-Monitor DPI Aware v2, 모든 좌표 물리 픽셀로 통일
관리자 권한 앱에는 입력 전달 불가(UIPI)안내 메시지 표시, README에 “관리자 권한으로 실행” 안내
대용량 이미지 메모리최대 높이 제한, 프레임은 증분 행만 보관, 미리보기는 축소본 사용
백신 오탐 (PyInstaller onefile)UPX 미사용, 해시 공개, 필요 시 onedir zip 병행 배포
